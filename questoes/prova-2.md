### Q21 · resposta-modelo

**(a)** Tipo I (fatias verticais): 0 ≤ x ≤ 4 e 0 ≤ y ≤ x/2. Tipo II (fatias horizontais): 0 ≤ y ≤ 2 e 2y ≤ x ≤ 4 (de y = x/2 isolamos x = 2y).

**(b)** ∫₀⁴ ∫₀^(x/2) 6x dy dx = ∫₀⁴ 6x·(x/2) dx = ∫₀⁴ 3x² dx = [x³]₀⁴ = **64**.

**(c)** ∫₀² ∫_{2y}⁴ 6x dx dy = ∫₀² [3x²]_{2y}⁴ dy = ∫₀² (48 − 12y²) dy = 96 − 32 = **64**. As expressões intermediárias diferem, mas o resultado final é o mesmo (Fubini).

**(d)** Inverter a ordem não é trocar as letras: para um y fixo, a "seta" horizontal entra na região sobre a reta y = x/2 (ou seja, x = 2y) e sai em x = 4. Só o desenho e a seta entra/sai mostram isso.

**(e)** O resultado 64 é a carga total acumulada sobre toda a região triangular (a densidade integrada vira um único número, útil para planejamento de capacidade).

### Q22 · resposta-modelo

**(a)** (1) O pré-processamento **não foi exportado junto** com o modelo: em produção os dados chegam brutos e não passam pelas mesmas transformações do treino. (2) `fit_transform` em produção reaprende média e desvio a cada requisição (deveria ser apenas `transform` com parâmetros aprendidos no treino), o que gera divergência entre treino e produção. Ambiente controlado e limpo do notebook ≠ dados novos, chegando um a um, nem sempre limpos.

**(b)** `ColumnTransformer` aplica a transformação certa por tipo de coluna (numéricas: imputer + StandardScaler; categóricas: imputer + OneHotEncoder) e é o passo de pré-processamento de um `Pipeline([('prep', ct), ('modelo', RandomForest...)])`. `pipeline.fit(X_train, y_train)` roda tudo na ordem certa; `joblib.dump(pipeline, 'pipeline.joblib')` salva o objeto completo; em produção, `joblib.load(...).predict(dados_brutos)`. O joblib é otimizado para objetos com muitos arrays NumPy (modelos) e é a opção recomendada pelo scikit-learn; ambos podem não abrir em outra versão de Python/biblioteca, então versionar o ambiente.

**(c)** O MLflow (tracking) registra, por *run*, os **parâmetros** (max_depth, n_estimators), as **métricas** (acurácia, F1) e os **artefatos** (modelo, gráficos), agrupados em experimentos. Assim se compara e reproduz qual configuração gerou qual resultado, sem arquivos como `modelo_final_v2_AGORA_VAI.pkl`.

**(d)** O SHAP explica **cada previsão individual**: valor base (previsão média) + contribuição de cada variável (que empurra para cima ou para baixo) = previsão do modelo. Isso responde "por que este cliente foi sinalizado". A importância global só diz o peso médio das variáveis no modelo inteiro, sem explicar um caso específico.
